# 预筛选与 AI 校对操作

本文面向翻译比较工作台的使用者。安装和基本流程见 [README](../../README.md)，导入辅助资料见 [辅助表格](auxiliary-tables.md)。修改提示词、调度或结果判定的开发规则由 [AGENTS](../../AGENTS.md) 指向的契约维护。

## 预筛选

在「预筛选」中运行规则与相似度粗筛，再决定哪些行需要模型判断。标点或符号仍有差异的行，即使显示相似度 100%，也会留给 AI 校对。

勾选「仅看预筛结果」可集中查看结果；「确认预筛」确认当前筛选范围内的通过行，完成后会取消这项勾选并保留其他筛选条件。已人工确认的行会跳过，日志显示「人工确认跳过 N 行」。重新打开页面时，可由本地服务恢复上一轮预筛结果。

## 配置连接与模型预设

保持控制台服务运行，在「AI 辅助校对 → 校对设置」填写接口类型、地址、模型、API Key 和并发上限。支持 Claude 原生接口、OpenAI-compatible 服务和 Ollama 等本地接口。三语模式可选择校对 B 或 C，双语模式只校对 B。

配置可另存为模型预设。提供商名称用于区分服务或账号，不同提供商可以保存同名预设；同一提供商下的同名预设经确认后更新。选择「新建预设」会清空连接和模型参数，再填写并另存即可。

「推理强度」按模型声明的能力显示。刷新模型列表后，能力信息随配置和预设保存；不支持或无法确认的档位回到「模型默认」。

并发由程序自动调节，只需设置不小于 1 的「并发上限」，默认 3。遇到限流或过载会自动降速；「当前配额」是当前允许的并发，「配置上限」是适用预设上限之和，实际运行数还受队列数量与退避等待影响。「运行 0 行」表示此刻没有请求正在执行；限流等待时会显示「限流退避」或「冷却中」，运行区标出距下次尝试的时间，到期后重新尝试派发。

## 选择阶段与开始范围

| 阶段 | 用途 |
| --- | --- |
| 事实初审 | 逐行核对事实、语义与规范 |
| 文学复审 | 复核初审提出的修改，检查表达与行文 |
| 终审仲裁 | 对分歧和待终审记录定案 |

每张阶段卡片选择预设后，点「添加」才会适用。仅选中候选不会启用；阶段二、三的适用列表为空时不启用。阶段一未添加预设时使用主配置。阶段三可以独立配置并处理已有复审分歧，无需先启用阶段二。

- **阶段卡片的开始 / 停止**只控制该阶段。单独开始复审或仲裁，只处理启动时已有的候选；上游之后新增的候选可在下一次启动时处理。
- **一键开始**在全部阶段空闲时，将已启用阶段按行衔接；上游完成一行即可交给下游，不必等整批完成。未启用阶段会跳过。
- **一键停止**停止全部正在运行的阶段。
- **继续剩下的**保留已有结论与人工确认；已有初审、只差复审的行直接进入复审，已有复审、只差仲裁的行直接进入仲裁。
- **从未人工确认处开始**会清除相应阶段的旧方案与异常后重新处理。有其他阶段正在运行或等待启动时，该选项不可用。

模型未填或适用预设失效时，「开始」会禁用，悬停可查看原因。「一键开始」要求所有参与阶段均有有效模型，独立开始只检查自身阶段。

## 同阶段使用多个预设

在卡片的「适用 (N)」下拉中添加多个预设，各自使用自己的并发上限，阶段总并发为各预设当前并发之和。下拉可查看每个预设的请求数、配额、上限、排队数、触顶状态及退避或冷却倒计时。单个预设等待时，其余可用预设继续处理；只有全部可用预设都在等待且没有请求正在执行时，阶段标题才显示等待状态。

运行中可新增或移除预设。移除后，尚未派发的行改派给其他预设，已发出的请求继续完成；新增预设立即参与。全部适用预设移除后，该阶段改用阶段配置处理剩余行。

## 阅读结果与统计

完成终审的行只定案为「建议修改」或「无需修改」。证据不足以支持修改时，终审保留原译并说明原因。「待终审」、存疑记录和调用异常都需要继续处理，不能当作无需修改。

「修改结果」的版本栏可查看本行已有完整的阶段改案；尚待执行的版本不能切换，停用阶段后仍可查看历史方案。局部修改提议不会直接变成可写回的完整段落。AI 结论需要人工复核，源文本只在显式写回时改变。

卡片数字可点击筛选，再次点击当前项取消，也可用「清筛选」清除：

- **进度**：初审按全页计算，复审和仲裁按当前候选计算。上游新增候选时，下游总量增加，百分比可能回落；下游暂时到达 100% 不代表整本书已审核完毕。
- **待复审 / 待仲裁 / 异常**：对应当前仍需处理的行，点击可集中查看。旧轮次记录会保留，但不会代替本轮结论。
- **修改率**：建议修改行数占已有自动结果行数的比例；待终审、未定案记录与预筛通过行计入分母，调用失败不计入。悬停可看明细。
- **缓存命中率**：来自接口返回的输入 token 用量，表示缓存读取 token 占输入 token 的比例；未报告时显示「—」，只有部分调用报告时标为「部分」。它不等于费用节省比例。

低分行可能进一步核对相邻行，无法定论的专名可能按规范档案配置的站点查证；查证依赖模型接口实际具备的检索能力。分析和尝试轨迹保留在备注中。

## 异常、停止与恢复

模型生成默认最多等待 5 分钟。超时后，本机停止等待，但提供商可能仍在处理，因此超时行不会自动重试。任务结束后，查看异常原因，再点对应阶段「开始 → 继续剩下的」重试。

持续限流会使阶段暂停、冷却后探测恢复；持续故障或配置错误会终止受影响阶段，已完成结果保留。其他阶段可继续运行。页面提示「控制台服务未更新」时，先重启控制台。

接口明确报告账号访问受限时，即使网关将其包装成 HTTP 429，程序也会终止受影响阶段，保留原始错误供排查。先检查网关与上游账号状态，解除限制后再点「开始 → 继续剩下的」；提高并发上限不能解除账号限制。

刷新页面或重启服务后，可恢复已保存的运行结果；「清除 AI 运行记录」清除运行缓存，长期备注和人工确认另行保存。复审或仲裁失败时，上一阶段的方案仍保留，异常原因记录在审核备注中。

停止后仍可查看已完成结果。备注面板出现「尚未保存」时，请等待保存成功，或先导出备份再关闭页面；详见 [备注与写回](notes-and-writeback.md)。

## 选择规范与高级配置

在「校对设置 → 特化规范」中选择通用小说规范或公开示范档案。不同作品的译名、角色说话习惯通过生成前选择的辅助表提供，不会因切换规范而自动改变表格。

自定义规范档案需要修改 JavaScript 配置。私有文件可以放在被 Git 忽略的 `src/workbenches/translation-compare/ai/profiles/local/` 目录，例如建立 `work-profile.js`：

```js
module.exports = {
  extends: "novel",
  name: "我的小说规范",
};
```

这个最小配置沿用小说规范，只修改显示名称；需要补充条目时，再按 [档案叠加规范](../contracts/ai-proofread-contract.md#档案注册与叠加规范) 添加差异字段。叠加后仍沿用基底的规范 id，下拉里显示合并后的同一项。

也可把文件放在仓库外，启动服务前设置 `TRANSCOMPARATOR_PROFILE_FILES` 指向文件；多个文件用分号或逗号分隔。新增或修改档案后需要重启控制台服务；已有翻译页面要更新默认提示词时，另执行「应用新布局」并 F5。

字段合并、按行规则与上游规范同步属于维护实现的内容，见 [AI 校对契约](../contracts/ai-proofread-contract.md)。不要把模型的默认知识当作本项目译名表或原文证据。
