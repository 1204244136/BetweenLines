# 预筛选与 AI 校对操作

本文面向翻译比较工作台的使用者。安装和基本流程见 [README](../../README.md)，导入辅助资料见 [辅助表格](auxiliary-tables.md)。修改提示词、调度或结果判定的开发规则由 [AGENTS](../../AGENTS.md) 指向的契约维护。

## 预筛选

在「预筛选」中运行规则与相似度粗筛，再决定哪些行需要模型判断。标点或符号仍有差异的行，即使显示相似度 100%，也会留给 AI 校对。

勾选「仅看预筛结果」可集中查看结果；「确认预筛」确认当前筛选范围内的通过行，完成后会取消这项勾选并保留其他筛选条件。已人工确认的行会跳过，日志显示「人工确认跳过 N 行」。重新打开页面时，可由本地服务恢复上一轮预筛结果。

## 配置连接与模型预设

保持控制台服务运行，在「AI 辅助校对 → 校对设置」填写地址、模型、API Key 和并发上限。接口类型不需要选择，也不占界面：地址指向本机或局域网时按本地 OpenAI 兼容服务处理，指向 Anthropic / Claude 或 `/v1/messages` 端点时按 Claude 原生接口处理，其他公网地址按 OpenAI-compatible 处理。三语模式可选择校对 B 或 C，双语模式只校对 B。

配置可另存为模型预设。提供商名称用于区分服务或账号，不同提供商可以保存同名预设；同一提供商下的同名预设经确认后更新。选择「新建预设」会清空连接和模型参数，再填写并另存即可。

「推理强度」按模型声明的能力显示。刷新模型列表后，能力信息随配置和预设保存；不支持或无法确认的档位回到「模型默认」。

并发由程序自动调节，只需设置不小于 1 的「并发上限」，默认 3。遇到限流或过载会自动降速。预设卡的「总并发」显示此刻实际运行数与该预设的共享上限，三个阶段共同使用这一上限。实际运行数还受当前允许配额、待办数量与退避等待影响；悬停预设可查看配额、排队及等待明细。「当前并发 0」表示此刻没有请求正在执行；限流等待时会显示「限流退避」或「冷却中」及距下次尝试的时间，到期后重新尝试派发。

### OpenCode Go

在「校对设置」中新建预设，地址填写 `https://opencode.ai/inference/go/openai/v1`（会按地址自动识别为 OpenAI 兼容接口）。API Key 使用已订阅 Go 的 OpenCode 工作区的个人密钥。

已有预设可继续使用 `https://opencode.ai/zen/go`、`https://opencode.ai/zen/go/v1` 或 `https://opencode.ai/zen/go/v1/chat/completions`。

点模型旁的「刷新」从列表选择，或通过「自定义...」输入模型 ID，例如 `glm-5.3-flash`。推理强度可保留「模型默认」。点「测试」检查模型响应后保存预设。

OpenCode Go 面向发送典型编程代理流量的客户端。批量翻译校对是否适用 Go 额度，以 OpenCode 对该用途的说明为准。 [OpenCode Go 使用范围](https://opencode.ai/v2/docs/console/go/#where-can-i-use-it)

## 共享预设池与阶段分工

| 阶段 | 用途 |
| --- | --- |
| 事实初审 | 逐行核对事实、语义与规范 |
| 文学复审 | 复核初审提出的修改，检查表达与行文 |
| 终审仲裁 | 对分歧和待终审记录定案 |

在共享池选择预设后，点「添加」才加入。每个新预设默认勾选三个阶段；取消某个阶段后，该预设不接该阶段任务。旧版配置首次载入时会合并为一个池，并保留原来的阶段分工。

池顶部共用一条工具栏，左侧是池标题、添加预设、阶段优先级、运行模式和启停，右侧是缓存命中与最终审核统计。宽屏同一行展示，空间不足时自然换行，工具栏高度随内容调整；每个统计徽标的文字与数字保持在一起。预设在左侧纵向排列，三个阶段在右侧上下排列，整体高度随阶段内容调整。预设卡片左侧按两行组织名称与阶段勾选，右侧的移除按钮放在总并发文本前，两者始终同排；名称最多显示两行，完整名称可悬停查看。预设较多时仅左侧列表滚动，不把整块面板撑高。细滚动条放在列表左边，悬停或键盘聚焦时加深，与右侧管道起点错开；添加预设时卡片宽度保持稳定，列表也可通过键盘滚动。阶段标题右侧显示运行等待与进度说明，指标紧凑排列，进度条贴近卡片底部。阶段分工、优先级和指标较多时允许换行增高，保持字号可读。手机等窄屏将预设与阶段改为单列，限制预设列表高度并隐藏管道，阶段勾选仍然生效。

勾选阶段后，预设与对应阶段之间自动生成管道。虚线表示已分配但当前空闲；浅蓝实线表示正在执行，深蓝水流沿管道覆盖到箭头后恢复浅色。管道越粗，表示这条连接当前实际运行的请求越多；水流循环越快，表示这个预设在该阶段的平均请求延迟越低。平均延迟按已完成请求样本累计，成功、失败和超时均计入，取消不计入；没有样本时采用中性的默认节奏。阶段统计、并发或延迟刷新时保留当前水流进度，避免重新从头播放。

预设右侧的移除按钮与总并发文本作为一组，随实际生成的管道起点组上下边界动态垂直居中。管道不常驻数字；悬停时该管道变为橙色，用一份提示逐行显示预设、阶段、状态、当前并发与平均延迟，暂无延迟数据时显示 `—`，不再重复预设总量。移开鼠标后恢复原色。

每个预设只有一份并发上限，三个阶段共同使用。例如高能力预设允许三个阶段、优先仲裁时：仲裁有待办就优先处理仲裁；暂时没有仲裁待办时，可以处理初审或复审，后续有仲裁任务则在空出请求位置时优先接手。已经发出的请求会正常完成。

阶段优先级可以关闭；开启时数值越大越优先。阶段开关、拒答回避、故障停用和限流等待始终生效，优先级不会绕过这些限制。自动分配利用本轮实际反馈：超时较多的预设倾向较短内容，容量较低的预设倾向少量剩余任务；不会推测模型的审核质量。

## 启动池与循环续跑

- **常规模式**：处理本轮待办并逐行衔接下游；保留未解决异常，完成本轮后停止。
- **循环模式**：异常行各自等待后重新派发，空闲预设可接手已到期的重试，无需等待其它阶段的慢请求全部结束；成功后自动推进复审和仲裁，直到本次范围完成或没有可行的重试路径。阶段一暂时空闲后仍可继续处理自己的异常行。
- **启动池**始终继续已有进度。已有初审、只差复审的行直接进入复审，已有复审、只差仲裁的行直接进入仲裁；保留人工确认，不清空备注。
- **停止池**停止整个池的派发与正在执行的请求，已完成结果保留。

预设池为空、模型未填或预设失效时不能启动，界面会说明原因。三张阶段卡片用于查看进度与筛选结果，不再分别配置预设或启动阶段。

循环模式会记住本次运行中同一行、同一阶段的拒答预设，改用其他允许的预设。每个预设对同阶段同行累计三次普通失败后不再接手，限流另按退避与冷却处理；认证、账号或余额错误停用整个预设，其他健康预设继续。全部选择均已拒答、全部预设不可用、某阶段未配置可用预设或重试机会耗尽时，会保留异常并显示阻塞，不能把它当成审核完成。

运行中可增删预设或调整阶段分工、优先级。移除后，尚未派发的任务重新分配，已发出的请求继续完成；池为空时停止派发，不会偷偷改用主配置。预设的配额、运行数与等待状态按整个池统计，不能把三个阶段的显示值相加当作额外额度。

## 阅读结果与统计

完成终审的行只定案为「建议修改」或「无需修改」。证据不足以支持修改时，终审保留原译并说明原因。「待终审」、存疑记录和调用异常都需要继续处理，不能当作无需修改。

「修改结果」的版本栏可查看本行已有完整的阶段改案；尚待执行的版本不能切换，停用阶段后仍可查看历史方案。局部修改提议不会直接变成可写回的完整段落。AI 结论需要人工复核，源文本只在显式写回时改变。

卡片数字可点击筛选，再次点击当前项取消，也可用「清筛选」清除：

- **进度**：初审按全页计算，复审和仲裁按当前候选计算。上游新增候选时，下游总量增加，百分比可能回落；下游暂时到达 100% 不代表整本书已审核完毕。
- **待复审 / 待仲裁 / 异常**：对应当前仍需处理的行，点击可集中查看。旧轮次记录会保留，但不会代替本轮结论。
- **修改率**：建议修改行数占已有自动结果行数的比例；待终审、未定案记录与预筛通过行计入分母，调用失败不计入。悬停可看明细。
- **缓存命中率**：来自接口返回的输入 token 用量，表示缓存读取 token 占输入 token 的比例；未报告时显示「—」，只有部分调用报告时标为「部分」。它不等于费用节省比例。

低分行可能进一步核对相邻行，无法定论的专名可能按规范档案配置的站点查证；查证依赖模型接口实际具备的检索能力。分析和尝试轨迹保留在备注中。

## 异常、停止与恢复

模型生成默认最多等待 5 分钟。常规模式保留超时行，供下次启动继续；循环模式允许延后重新尝试。超时只代表本机停止等待，提供商可能仍在处理，循环重试可能产生额外请求和费用。

持续限流会使受影响预设进入冷却，之后自动探测恢复；持续故障或配置错误会停用受影响预设。其他可用预设继续工作，无法处理的行保留为异常或阻塞。页面提示「控制台服务未更新」时，先重启控制台。

接口明确报告账号访问受限时，即使网关将其包装成 HTTP 429，程序也会停用该预设，保留原始错误供排查；其余健康预设继续运行。该停用不会自动探测恢复。先检查网关与上游账号状态，解除限制后再启动池；提高并发上限不能解除账号限制。

接口返回 HTTP 402，或明确报告余额不足、可用额度耗尽时，「异常」的悬停明细会单列「余额或额度不足」，日志提示检查 API Key 的余额、额度，或更换可用预设。该预设会停用，其他健康预设继续运行；补足余额、恢复额度或更换预设后，再启动池。即使提供商把额度耗尽包装成 HTTP 429，也不会按普通限流反复等待。已有失败备注会保留，更新布局后也能显示这项分类。

刷新页面或重启服务后，可恢复已保存的运行结果；「清除 AI 运行记录」清除运行缓存，长期备注和人工确认另行保存。复审或仲裁失败时，上一阶段的方案仍保留，异常原因记录在审核备注中。

停止后仍可查看已完成结果。备注面板出现「尚未保存」时，请等待保存成功，或先导出备份再关闭页面；详见 [备注与写回](notes-and-writeback.md)。

## 选择规范与高级配置

在「校对设置 → 特化规范」中选择通用小说规范或公开示范档案。不同作品的译名、角色说话习惯通过生成前选择的辅助表提供，不会因切换规范而自动改变表格。

自定义规范档案需要修改 JavaScript 配置。私有文件可以放在被 Git 忽略的 `src/workbenches/translation-compare/ai/profiles/local/` 目录，例如建立 `work-profile.js`：

```js
module.exports = {
  extends: "novel",
  name: "我的小说规范",
};
```

这个最小配置沿用小说规范，只修改显示名称；需要补充条目时，再按 [档案叠加规范](../contracts/ai-proofread-contract.md#档案注册与叠加规范) 添加差异字段。叠加后仍沿用基底的规范 id，下拉里显示合并后的同一项。

也可把文件放在仓库外，启动服务前设置 `TRANSCOMPARATOR_PROFILE_FILES` 指向文件；多个文件用分号或逗号分隔。新增或修改档案后需要重启控制台服务；已有翻译页面要更新默认提示词时，另执行「应用新布局」并 F5。

字段合并、按行规则与上游规范同步属于维护实现的内容，见 [AI 校对契约](../contracts/ai-proofread-contract.md)。不要把模型的默认知识当作本项目译名表或原文证据。
