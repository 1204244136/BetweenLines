# 辅助表格导入

本文面向准备译名表或说话习惯表的使用者。工作台的安装和基本流程见 [README](../../README.md)；修改解析、匹配或提示词实现时，按 [AGENTS](../../AGENTS.md) 进入领域契约。

## 选择与更新

在控制台的「辅助表格」中，生成前分别选择「译名表」和「说话习惯表」。两项都可留空，留空表示不挂载；可以选择本机文件，也可以粘贴路径，多文件路径用分号分隔。

两类表均支持 **XLSX、CSV、TSV、JSON**。选择随项目保存，切换项目时恢复。修改选择或表内容后，重新生成工作台，让页面标签与新表一致。切换 AI 特化规范不会改变已挂载的表。

工作台的「校对设置」显示 `未挂载`、`文件名（N 条）` 或 `加载失败`，悬停可看完整路径与错误。表文件需要保留在本机原位置，校对运行时仍会重新读取。

## 列名与最小示例

按表头识别列，列顺序不限。可以沿用原表的专用列名，也可以使用通用中英文列名；未知列不参与判断，不会根据列的位置猜测用途。

| 表格 | 必需列 | 常用可选列 | 原格式兼容 |
| --- | --- | --- | --- |
| 译名表 | `原文` / `source` + `译名` / `target` | `读音` / `ruby`、`类型` / `type`、`其他译名` / `other`、`备注` / `memo` | `Base_Ori`、`Base_Trans`、`Ruby_Ori`、`Ruby_Trans`、`Other_Fandom`、`Type`、`Memo1` / `Memo2` |
| 说话习惯表 | `角色` / `character`，另需 `口癖` / `habit`、`项目写法` / `target`、`备注` / `memo` 中至少一列 | `类型` / `type`、`其他版本` / `other`、`参考写法` / `reference`、`首次出现` / `first_work` | `x版` / `x版本` / `本项目` / `成品`、`网翻`、`台版（转简中）`、`小说首次出现` 等 |

译名表最小 CSV：

```csv
原文,译名
星の港,星之港
```

说话习惯表 CSV：

```csv
角色,口癖,类型,项目写法,备注
林夏,オレ,第一人称,我,保持第一人称一致
```

也可直接用同名列建立 XLSX。描述型规则可只用「角色＋备注」，不要求登记固定的项目写法。

## 两类表共同的格式要求

- 首行放表头，不要在前面放标题或说明，也不要使用合并表头。一行一个词条或角色规则，同一角色可有多行。
- 表头大小写不敏感，空格和连字符归一成下划线，例如 `Base Ori`、`Base-Ori` 与 `Base_Ori` 等价。归一后重名会报错；中文列名中间也不要任意加空格。
- **XLSX**：优先读名为 `data` 的工作表，否则读第一张。把实际数据放在该表中。公式仅读取已保存的结果，不计算公式；导入前在表格软件中重新计算并保存，或导出为值。旧 `.xls` 需先另存为 `.xlsx`。
- **CSV / TSV**：使用 UTF-8，可带 BOM。含分隔符、换行或双引号的值须用双引号包裹，值中的双引号写成两个双引号。
- **JSON**：支持对象数组（键为列名），或首项为表头的二维数组；也可用 `{ "rows": [...] }` / `{ "entries": [...] }` 包裹。例如译名表可写成 `[{"source":"星の港","target":"星之港"}]`。
- 多张表会合并使用，请避免同一词条或角色规则相互矛盾。

## 译名表的内容与标签

每行的原文与译名都应有值，缺少任一值的行不参与匹配。普通词条直接写原词即可。

沿用原表的分段注音格式时，原文中的 `【】` 标记读音加在哪里，读音列用逗号按顺序对应各个分段。例如 `【青山】【春人】` 对应 `あおやま,はると`；含逗号的 CSV 单元格需用双引号包裹。括号用于表内定位，匹配和展示时使用去掉括号的原文。

译名表为 AI 提供项目采用的译名。句中还有其他内容时，术语一致不能证明整句翻译正确，整行仍交给模型判断；只有整行有效内容都是术语、足以直接定案时才跳过模型。

生成后，页面会显示这些可展开标签：

| 标签 | 含义 |
| --- | --- |
| 纯术语 | 整行有效内容都是术语，预筛时可直接判定 |
| 术语注入 | 术语作为提示提供给 AI，整句仍需判断 |
| 术语冲突 | 项目译名与译文写法不一致，作为线索交给 AI 核对 |

短词、读音撞车、只出现姓氏或名字片段等证据不足的情况不会直接判为缺陷。带注音的非人名词条还会核对原文与译文中的注音证据；表中登记了读音，不代表每次出现同样的汉字都指该专名。标签表示辅助线索，真实结论以审核备注为准。

## 说话习惯表的内容与空值

角色名应与正文中的写法一致；没有角色名的行跳过。项目写法是本项目采用的写法，原格式中的「x版」与通用的「项目写法」表示同一用途；其他版本、参考写法只作对照。

- **有具体写法**：用来检查说话特色是否体现，并提醒模型保留已采用的写法。
- **填 `-`**：明确不作特殊处理，也不套用其他版本的特殊写法；不会据此要求补回口癖或扣分。
- **留空**：没有登记固定写法，可以通过备注描述句式或语气；备注不会被当作译文必须出现的文字。

`类型` 的字面检测仍使用「第一人称」「接续词」「句首语气词」「句末语气词」「谓语形式」等现有中文值；复杂句式或称谓可在备注中描述。`首次出现` 只按 `S1_01` 一类作品编号过滤，普通项目请留空或省略该列。

工作台会结合章内角色线索提示「特色流失」，AI 校对时还会判断当前行的说话人。无法确认角色或证据不足时，不应把某个角色的习惯硬套到该行；请结合原文和上下文复核。

## 离线查看命中情况

不调用模型即可查看当前项目的辅助表命中情况：

```powershell
node scripts/term-prefilter.js --profile demo --limit 20
node scripts/term-prefilter.js --profile demo --from-snapshot
node scripts/term-prefilter.js --profile demo --all --json --out report.json
node scripts/speech-habit.js --profile demo --by volume
node scripts/speech-habit.js --profile demo --verify-source
```

`--profile` 使用规范档案 id。表格默认读取当前项目生成前的选择，可用 `--table` 临时指定另一张表。`--from-snapshot` 只提供构建期文本汇总；需要 JSON、报告文件或明细时，使用现算方式。

`--verify-source` 默认查找同级 `../index-X`，也可用 `INDEX_X_DIR` 或 `--index-x` 指定，核对三项内容：

1. 对应卷目录与正文文件是否齐全。
2. 快照章节与日文工作源的序章、行间、章节、终章结构是否对应。
3. 各角色口癖在工作源与快照原文列中的出现次数是否相符。

计数差异可能来自后记或插页被排除，也可能表示正文缺失，需要结合章节检查。该工作源是预处理产物，普通读音可能已被合并，不能用它断定原版没有注音。
