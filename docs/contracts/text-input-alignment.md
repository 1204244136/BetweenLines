# 文本输入、正文准入与对齐契约

修改输入登记、格式转换、正文过滤、标题探测、段落切分、跨语言对齐或模式裁剪前阅读本文。本文拥有输入与行数据的细则；模块依赖方向见 [模块边界](module-boundaries.md)，发布与写回见 [项目存储与写回契约](project-storage-writeback.md)，用户选择文件和运行命令见根 [README](../../README.md)。

## 文本角色与稳定索引

- 翻译比较接收一份原文和一到两份同级非原文。原文是准入边界：译本独有的特典、电子书附录、版权页、后记、译注和制作信息不进入最终比较。
- 每张表格行只包含一个完整原文段落，原文不得拆分、合并或跨行复用；非原文可为对齐、diff 和展示拆分或合并。缺少对应译文的原文段落仍须保留。
- 完整段落是共享稳定源索引；派生句子与完整发话带 `parentParagraphId`，不能替换段落索引。两个工作台独立持有结果、缓存与备注空间，不把翻译 rows 当作通用领域结果。
- 技术 pivot 只是实现选择，UI、文档和变量说明不得暗示某份非原文比另一份更权威。
- 未显式提供显示标签的新输入使用「原文 A / 非原文 B / 非原文 C」，不推定语言或地区版本；已有项目的显式标签原样保留。显示标签不参与项目身份，不因通用化命名重建备注空间。

## index-X 输入适配

本项目既支持通用本机输入，也适配同级 `../index-X` 或 `INDEX_X_DIR` 指定的上游项目。以下只维护本项目依赖的结构；正文规范的唯一来源仍是 index-X 的 `AGENTS.md`。

### 材料与证据边界

- 简中文本取版本化解压归档 `EPUB/`，或 `tools/package_cache_epubs.py` 生成的 `output/epubs/*.epub`；构建产物不存在时按 `EPUB/` 取用。目录与文件名形如 `【S1_01】作品名`。
- 日文原文取 `.cache/epub-work/japanese-text/` 或同步镜像。它是 `bw_preprocess.py` 的预处理产物：只保留特殊注音（当て字、外来语），普通读音已合并丢弃。「原文没写某标记」属于缺失证据，不能反过来指控译文多写注音、傍点或引号。
- 台版来自独立出版物，作为同级非原文材料使用。
- AI 译名与成品规范的来源、裁定优先级及三处同步义务统一见 [AI 校对契约](ai-proofread-contract.md#规范来源与同步义务)，不在输入契约复制。

### 编号与文件表头

- 作品编号分为 `S0`（阅读说明等非正文）、`S1`（旧约）、`S2`（新约，含 `S2_22r`）、`S3`（创约）、`S4`（某暗部的少女共栖）、`S5`（外典）、`S6`（日期短篇）。SS、SP 也占顺序号，编号不一定等于单行本卷号。
- `S5_AA_BB` 的 `AA` 是日文外典书库卷号，`BB` 是合订卷内独立作品号；缺号保留，不得重排。`S6_YY.MM.DD` 中点分隔的日期整体是作品标识，不是卷号或多级后缀。
- 正文文件为 `<表头>_<语义后缀>.xhtml`。内容序从 `-01` 开始，`-00` 非法；中日配对与排序使用稳定表头的内容序，例如 `S1_03-05`、`S5_01_03-02`、`S6_24.06.07-02`。SP 等使用稳定名称，例如 `S1_25-Uiharu_Kazari`。
- `_p-004`、`_Chapter2`、`_Afterwords` 等是页码、章节语义或语言侧包装，不属于表头。不得从 `ChapterN` 反推内容顺序，也不得用只识别两段数字的正则处理外典表头。

### 章节与 XHTML 结构

- `Prologue` 之前的内容聚合为内容序 `01` 的 `Before_the_Prologue`（引子）。
- `Afterwords` 之后紧接的连续正文页聚合为 `After_the_Epilogue`（尾声）。遇到纯插图、封底、著者介绍或版权等非正文页后立即进入书末附录，后续页面不再并入尾声或分配内容序。
- 后记（`Afterwords` / あとがき）不进入比较与说话人推断；尾声是正文故事叙述，必须进入。附录、版权页、介绍页是硬截止边界。
- 带正文的 XHTML 使用 L1–L6 固定行模板，正文首个 `<p>` 在第 6 行；无 h1/h2 时保留空行，中文列表型包装页允许 `<ul>` / `<ol>` 开标签占 L5。
- 标题块独占一个物理行，多层标题由 `heading-lines` 行内 span 表达；支持 ruby 与 noteref 内联标记。一个物理行只承载一个同级顶层正文块，该块是行对齐原子。
- 标题与 NCX/nav 不进入正文段落，因此不参与翻译比较；上游「原为英文的标题不得汉化」由上游结构门禁与人工保证，不在 AI 正文校对层实施。

## 格式转换与正文过滤

- `text-utils.js` 集中管理输入模式、章节探测 `chapterPatterns` 与边界裁剪。TXT 直接按 UTF-8 读取；非 TXT 优先经 Pandoc 转完整 linear plain text，再进行正文范围过滤、媒体占位过滤、段落切分和必要的 OpenCC 简繁归一化。
- `pandoc-utils.js` 只负责格式转换，不判断准入范围。EPUB 默认也走 Pandoc，内置 OPF/nav/spine reader 只作为诊断与 fallback；不得扩展为所有格式的主路径。
- 正文起止必须依据 Heading、标签或语义标记等结构边界，不能按字数、行数或纯文本正则猜测整书起点。
- 正文起点是最近一次结构边界（简介范围、章节标题、媒体占位）之后的第一个非前置块。`isLikelyBodyBlock` 只确认已经进入正文，不能据此重新选择起点而丢掉弱开篇。
- 明确排除特典、插画页、版权页、出版信息与目录。章节/行间标题不作为正文段落；数字节号不覆盖所属章名，普通正文块中的数字仍保留。临时结构标题标记不得进入最终段落、AI 输入或产物。

## 模式裁剪与签名

- 双语产物只含实际存在的两列；三语产物完整保留三列。裁剪覆盖 `input-selection.json`、`paragraphs.json`、`jp-align.json`、`translation-compare.{json,csv,html}`、页面控件、AI 提示词与日志，不能留下第三列的键、标签、空占位或 hidden 控件。
- `validateSelection` 在双语模式裁去 `files` / `labels` / `startMarkers` 中的 `tw`。`loadParagraphs` 只返回 `cn` / `jp`，不写空 `tw` 数组，日志按 `activeLangs()` 打印计数。
- 行输出统一由 `rowFieldsFor(mode)` 决定；双语行不带 `tw` / `twCn` / `twChars` / `refinedScore`，包括 `counts`、CSV 列、页面标签和内嵌数据。
- 模式裁剪只能删字段，不能改变 `projectKey`、`rowsSignature`、`signature`。这些键定位备注空间与写回，只有源文本或实际对齐结果变化才能改变它们。

## 对齐产物与展示标签

- `align_jp.py` 负责跨语言语义对齐。移动仅允许 `1:1`、`1:2`、`1:0`、`0:1`，保证每个输出行最多一段原文；非原文侧可拆段。双语模式的技术 pivot 固定为 `cn`。
- `jp-align.json` 的 `groups` 是唯一对齐数据，组内区间用 `pivotStart` / `pivotEnd`。旧快照中原文与目标段数相等的多原文组可拆为 `1:1`；原文段数更多时拒绝构建，并要求重新运行 `npm run align:jp`。
- 三语构建对齐两份非原文；双语构建直接以非原文段落作为技术 pivot 单元。不得恢复没有 reuse tracking 的 naive paragraph-number fallback，也不得让 semantic groups 与 fallback 重复使用同一原文长段。
- 对齐质量标签来自算法分数或规则推断，不能人工硬编码。分数与阈值变化须检查 Python 对齐、JS 行组装和展示层口径，并兼容旧快照的标签显示；模块归属见 [模块边界](module-boundaries.md#翻译构建边界)。
- 说话人双语 TXT/文档使用整篇单调预对齐；双 EPUB 先按 XHTML 完整表头分段再预对齐。持久化 `alignment` 只留摘要，中间预对齐行不落盘；完整发话与证据注意力规则见 [说话人边界](module-boundaries.md#说话人工作台边界)。

## 修改后的验收

输入格式、正文过滤、标题探测、段落切分或对齐发生行为变化时，除领域定向测试外，必须用本机样本重新导出、对齐并构建；说话人受影响时另重新生成。纯文档调整或模块结构移动不要求重跑语义对齐。

```powershell
node --test scripts/text-utils.test.js scripts/epub-utils.test.js scripts/build-compare.test.js scripts/row-source-only.test.js
npm run align:jp && npm run build
```

验收必须同时确认：原文段落与表格行严格 `1:1`；空原文、异常行数处理正确；重复长原文未复用；媒体占位、后记和附录未进入正文；两侧首段内容对应；双语产物 `bilingualLeakage` 为 `false`，`counts` / `rowKeys` 无第三列字段。正文过滤修改还要运行基准回归，确认行索引稳定。

真实样本放在仓库外，路径仅存忽略文件或环境变量。所需材料包括简中 EPUB/解压目录、日文对齐工作源、可选台版解压目录；不把源文件、绝对路径、样本目录名或生成物写进提交、默认配置或日志说明。公开样例与重型文件的边界见 [改动工作流](../agents/change-workflow.md)。
