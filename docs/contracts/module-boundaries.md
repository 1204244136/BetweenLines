# 模块职责拆分记录

分析日期：2026-09-25。范围覆盖控制台入口、翻译构建链和 AI 服务对页面渲染的依赖。

## 判断依据

按不同的变化原因、共享状态、依赖方向与可独立验证性识别职责。行数仅作定位线索；同一算法或同一模板不按行数机械切碎。保留原有兼容入口，实际实现只有一个来源，避免复制逻辑。

## 已完成

### 控制台

原 input-server.js 为 911 行，同时处理安全策略、请求体解析、文件选择、输入持久化、任务状态、页面响应及全部业务路由。现在入口为 142 行，只保留依赖组装、鉴权、路由分派和服务生命周期。

- http-json.js：JSON 请求解析及响应格式。
- request-security.js：Host、Origin、Fetch-Site、令牌校验及令牌注入。
- input-files.js：本机文件扫描、选择、校验与翻译输入选择。
- speaker-runtime.js：说话人输入持久化及任务运行状态，构建和写入依赖可注入。
- artifact-response.js：静态资源和生成页面的响应。
- routes/：输入、状态、项目、生成、写回、AI 各自拥有路由；只接收需要的运行实例与配置。

路由返回是否命中，未命中不得消费请求体。入口统一鉴权后再分派，子模块不导入服务入口。既有响应码、接口路径、写回行序参数及生成互斥规则保持不变。

### 翻译构建

原 build-compare.js 为 1466 行，混合对齐、备注恢复、模型下拉选项、产物裁剪及 HTML。现在入口为 189 行，保留构建、发布与快照重渲染流程，原导出继续转发到同一实现。

- alignment-artifact.js：读取对齐产物、旧字段兼容、单原文段落校验。
- row-alignment.js：非原文对齐及比较行组装，算法与阈值原样保留。
- row-output.js：模式字段、签名、导出行、客户端行与 CSV。
- notes-recovery.js：根据签名/内容/锚点匹配历史记录的纯函数。
- model-options.js：模型选项规范化及恢复的纯函数。
- render-workbench.js：HTML 渲染及静态资源即时读取。

构建器原先在导入时读取但不使用的静态资源副本已移除；真正渲染时仍重新读取资源。所有新模块留在工作台目录中，沿用现有模块缓存失效范围。

### AI 依赖边界

渲染器原先仅为读取默认值、评分规范化和提示词契约，就依赖整个 ai-proofread.js，导致页面构建加载任务运行状态。现在默认值归 proofread-defaults.js，评分与等级归 decision-score.js，提示词使用已有 proofread-contract.js。AI 服务也引用这两个模块并保持旧导出，避免规则出现两份。

## 尚未拆分的热点

本次完成的是可独立验证的职责边界，不代表全仓库所有大模块已原子化。

1. public/workbench-client.js（分析时 5848 行）：分页/渲染、布局缓存、备注编辑、AI 轮询及键盘导航仍共享页面状态。下一步应先明确 notes、filteredRows、activeRowId 的所有权，再提取控制器；不能仅拼接拆开的脚本来宣称解耦。
2. ai/ai-proofread.js（分析时 4080 行）：本次只抽离共享配置与评分；任务调度、多阶段执行、提示词上下文和结果展示仍待进一步拆分。应先显式传递 runId、日志与结果存储，保持门禁顺序和增量轮询语义。
3. src/ingest/writeback.js（分析时 803 行）：候选定位、单调锚点推进、格式保留及写入事务需联动，拆分前必须保留歧义拒写与备份失败行为的整链验证。

剩余热点列为后续范围，不在本次改动中改写其业务行为。
