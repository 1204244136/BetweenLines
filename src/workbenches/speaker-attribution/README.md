# 说话人归属工作台

该工作台帮助审阅者根据邻近的叙述上下文，确认每个派生行是谁说的。它呈现的是分页的审阅工作空间，而不是完整的静态表格；将人工判定保存在浏览器本地存储（localStorage）中，并支持导出审阅结果。在不改变输入与对齐契约的前提下，后续可以接入模型推断。

仅由 `「…」` 或 `『…』` 包裹的完整发话才会生成审阅行。即使一个带引号的发话包含多个句末标点，它仍然保持为单独一行；临近的叙述内容作为上下文提供，其本身不作为说话人判定行。

双语审阅默认采用严格的逐行对齐：一行完整发话最多对应另一侧的一行发话。多余的或结构差异较大的发话行作为 `0:1` 或 `1:0` 行保留显示，而不是强行合并到临近行中。同段落拆分合并仅保留用于显式对齐诊断，在工作台构建中已禁用。

## 输入模式

- 单语模式：通过 `--source` 传入一个源文件。
- 双语模式：传入 `--source` 和 `--parallel`。工作台在生成审阅行之前始终会先进行预对齐。当两个文件均为 EPUB 时，它首先按完整稳定的文件名表头配对正文 XHTML 文档，然后仅在匹配的同表头正文块内部执行单调的感知证据对齐。低置信度和未匹配的源行或平行行将保持可见，而不会被悄悄丢弃。

示例：

```powershell
npm run build:speaker -- --source "C:\path\source.epub"
npm run build:speaker -- --source "C:\path\source.epub" --parallel "C:\path\translation.epub" --source-lang jp --parallel-lang cn
```

生成的文件默认写入 `out/runtime/speaker-attribution/`：`speaker-attribution.html` 和 `speaker-attribution.json`。

对于双语行，UI 会展示结构对比信号，例如共享片段、数字、句末结构和长度。这些信号仅作为对齐证据；它们不是语义等价性判定。

每个判断行还会经过 `src/workbenches/speaker-attribution/attention.js` 的证据注意力层：上下文保留完整引号发话，只对引号外叙述做句子切分；再按邻近度、说话动作词、引用式 `と、Xは…`、疑似称谓和对齐信号压缩 prompt 输入。`evidence-attention-v2` 会用说话动词（`言った`、`叫び返す`、`答えた`…）和引用式 `と` 前的主语粒子（`は/が/も`）提取候选，剥离 EPUB `<ruby>` 标记，并排除非人物名词和动词连用形造成的误报。注意力权重是检索排序，不是模型事实；候选不足或证据冲突时，prompt 要求模型返回 `unknown` 或 `needsContext`，禁止猜测。工作台可复制当前行的结构化 JSON prompt，默认不需要配置模型也能使用这套确定性筛选。

注意力分数表达的是“归属证据强度 / 审阅优先级”，不是正确率：有明显可辨识证据的行会被标为高/中，只能靠对话轮次推断的行保持低并建议人工复核。双语模式的对齐比较在跨脚本输入（如日文原文 vs 中文主文本）下会降低字符重叠权重、改用长度、句末结构和对话标记等结构信号加权，避免“对齐置信度”被语言差异整体压成低。

EPUB 表头匹配适配 index-X 的命名规则，使用类似 `S1_03-05`、`S2_22r-01`、`S5_01_03-02` 和 `S6_24.06.07-02` 的稳定标识符。语言侧的外层包装（例如 `_p-004`、`_Chapter2` 和 `_Afterwords`）不会改变表头。导航文档和非正文 spine 项（包括封面、版权页、制作信息以及 `_Afterwords` 后记文件）在对齐前会被排除；而序章前的 `_Before_the_Prologue`（引子）与后记后**紧接的连续正文页** `_After_the_Epilogue`（尾声）均作为正文保留——后记之后一旦遇到纯插图页、封底、著者介绍或版权页，即从该页起进入书末附录，其后的页不并入尾声、也不分配内容序（上游 `index-X` 的口径，见其 `AGENTS.md` 的「中文 XHTML 文件名与包装后缀」）。如果两个 EPUB 文件没有可用的共同表头，工作台会保留全局单调 fallback 以保持兼容。

该功能使用来自 `src/ingest/line-units.js` 的派生行单元，保留 `parentParagraphId` 和源文本偏移量，以便句子级结果始终可以追溯回完整的源段落。它拥有自己的结果模型，包括：

- 预测说话人和候选说话人；
- 置信度与证据；
- 用于判定的上下文单元；
- 状态（如 `unknown`、`narration`、`multiple` 或 `needs-review`）；
- 人工覆盖结果及其原因。

说话人结果不得作为翻译校对备注存储，也不得作为列追加到翻译比较表中。生成的 JSON 包含分析类型、行单元版本、对齐版本和分析 key，以便后续的模型/规则版本可以使用独立的缓存。
